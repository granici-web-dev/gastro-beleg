# КОНТЕКСТ ЭКОСИСТЕМЫ (обязательное чтение)

## Три продукта на одном ядре

**GastroBeleg** (gastrobeleg.de) — основной продукт, в активной разработке. Входящие документы для независимых немецких ресторанов: владелец фотографирует накладные/счета (или пересылает в WhatsApp/email, или получает E-Rechnung), система распознаёт их ПОПОЗИЦИОННО (не только сумму — каждую строку: товар, цена за единицу, количество, поставщик), даёт операционную аналитику и экспортирует предконтированные данные в DATEV для Steuerberater. Целевой прайс €89–149/мес. Первая POS-интеграция — ready2order (выбрана за открытый API и пересечение аудиторий).

**InvoiceGen** (рабочее название, домен не выбран) — исходящие счета для фрилансеров и Kleinunternehmer: бесплатный генератор корректных счетов PDF + XRechnung + ZUGFeRD. Стадия: продуктовая спека готова, дизайн впереди, стек выбирается после дизайна. Бенчмарк-конкурент: easyerechnung.de (это ЧУЖОЙ продукт, не наш). Роль в экосистеме: SEO-воронка (бесплатные инструменты → аккаунты → платные тарифы → кросс-селл).

**KanzleiBeleg** (kanzleibeleg.de) — портал для Steuerberater, связующее звено: StB видит документы/данные своих мандантов из обоих продуктов. Стратегическая роль: канал дистрибуции (один StB ведёт 50–200 малых бизнесов и может приводить их пачками). Строится третьим, вырастает из GastroBeleg.

## Ключевые стратегические решения (уже приняты — не пересматривать в отчётах, но учитывать)

1. **Позиционирование против DATEV: «рельсы, не соперник».** DATEV бесплатно/дёшево делает сканирование и передачу документов StB (Upload mobil, Belege online, ~€11–25/мес за весь стек). Мы НЕ конкурируем со сканированием. Наша ценность — слой ПЕРЕД DATEV: попозиционный интеллект (цены, маржа, сверка), которого у DATEV нет и который ему строить неинтересно (DATEV работает на уровне документа и проводки, для канцелярии, не для владельца).
2. **Юридическая граница StBerG/RDG — жёсткая.** Никаких персональных налоговых рекомендаций. Только «информация и триаж» на собственных данных клиента. Идея Behördenpost (расшифровка писем от ведомств) отложена именно из-за этого риска.
3. **Полевые продажи важнее платной рекламы для гастро.** Платный трафик на рестораны работает плохо (таргетинг владельцев ненадёжен, B2B-решение не импульсное). Основной канал: продажник с живым демо (сфотографировать накладную со стойки при владельце) + StB-канал + поставщики как рефереры. Платная реклама — фокус на InvoiceGen и поддержку поля (ретаргетинг, гео).
4. **Никакого раздувания MVP.** Все идеи из Приложения A — Phase 2+. MVP GastroBeleg: ingestion → распознавание → DATEV-экспорт + базовые алерты.
5. **Ядро расширяемо**: типы документов (Rechnung, Lieferschein, Z-Bericht, Speisekarte, платформенные выписки...) — открытый enum; гастро-специфика — модуль поверх универсального ядра (для будущих вертикалей: Handwerk, малое производство).

## Что уже выяснено в предыдущих ресёрчах (не дублировать, опираться)

- **DATEV-стек владельца дёшев**: Unternehmen online ~€11/мес (10 юзеров), Belege online ~€3,75, Auftragswesen next ~€7, банк-сервис ~€1,33. Automatisierungsservice Rechnungen: ~5 центов/проводка, платит и настраивает канцелярия. В методичке DATEV идеальный сценарий ASR описан как «Hotel, Gaststätte, Bäckerei — 19% и 7% на одном счёте, от 50 документов/мес» — DATEV сам считает гастро идеальным кейсом автоматизации, но строит её для StB.
- **Реальные деньги ресторатора уходят не в софт, а в гонорар StB** за Buchführung (оценочно €150–400+/мес — ТРЕБУЕТ ПРОВЕРКИ, см. R3).
- **Карта POS малого гастро**: ready2order (~€35/мес, лучший прайс/качество, без WaWi с рецептурами), orderbird (€79/мес, гастро-специфичен, Pfand, DATEV-интерфейс +€10/мес, без склада), SumUp Pro (€45/мес), выше классом — Lightspeed, Gastronovi, Vectron/Shift4 (от 80 мест, KDS, мультифилиальность). Рынок фрагментирован.
- **Аналитика всех POS — односторонняя**: только выручка. Себестоимости не знает ни одна касса. WaWi-модули Gastronovi/Lightspeed требуют ручного ведения цен и рецептур — владельцы бросают.
- **Gründungszuschuss** (§93 SGB III): реален, до ~€20.700 за 15 мес (ALG I + €300 первые 6 мес, потом €300×9), нужны 150 дней остатка ALG I на день регистрации бизнеса, бизнес-план + fachkundige Stellungnahme (IHK/StB/банк), Ermessensleistung без правового притязания, бюджет программы недавно удвоен, AVGS даёт бесплатный коучинг.
- **E-Rechnung-мандат**: с 01.01.2025 все обязаны ПРИНИМАТЬ e-счета; выставление — поэтапно 2027 (оборот >€800k) / 2028 (все). Даты требуют перепроверки перед маркетингом (R4).

## Партнёрская структура (контекст для оценок «сколько это стоит строить»)

Соло-фаундер (продукт, продажи, маркетинг, финансы) + CTO-партнёр через свою IT-студию (доля 15–20% с milestone-вестингом, разработчики студии) + маркетинговое агентство (revenue share 10% cap €10k/мес, без доли; фокус InvoiceGen + поддержка полевого канала). Параллельно у фаундера консалтинговый проект SofaBelle (Румыния, мебельный ритейл) — источник методологии KPI-аналитики.

# PRIORITY 0 — блокирует текущие решения

## R1. API-ландшафт кассовых систем

**Зачем.** POS-данные — вторая половина главного уравнения продукта. Мы знаем себестоимость (из накладных), касса знает выручку; только соединение даёт маржу по блюдам, menu engineering, Wareneinsatz-Quote. От этого задания зависит порядок интеграций в roadmap и ответ продажника на возражение «а с моей кассой работаете?».

**Гипотеза для проверки (важнейшая): «Z-Bericht как универсальный коннектор».** Каждая немецкая касса формирует ежедневный Tagesabschluss/Z-Bericht — это ДОКУМЕНТ, а документы — наша суперсила. Если владелец пересылает Z-Bericht в наш обычный intake (WhatsApp/email), мы получаем выручку по категориям (иногда по продуктам) с ЛЮБОЙ кассой рынка — без API, без переговоров с вендорами, в день подключения. API тогда — апгрейд глубины, а не порог входа. Нужно проверить: что реально содержит Z-Bericht каждой системы и можно ли настроить авто-отправку.

**Вопросы по каждой системе — ready2order, SumUp, orderbird, Lightspeed Restaurant, Gastronovi, Tillhub, Vectron (Shift4), SIDES:**
1. Публичный API: есть? URL документации? Модель авторизации (OAuth/ключ)? Партнёрская программа обязательна — условия, стоимость, срок аппрува?
2. Данные через API: продажи попозиционно? По часам? Категории? Модификаторы? Историческая глубина? Webhooks или только polling?
3. Лимиты, sandbox, требования сертификации.
4. Экспорт без API: CSV/Excel, DATEV-экспорт, email-отчёты — что владелец может выгрузить руками?
5. Z-Bericht: что содержит (выручка по категориям? по продуктам?), формат (PDF/печать/email), настраивается ли авто-пересылка? Собрать образцы, где найдутся.

**Формат отчёта:** сравнительная таблица + рекомендованный порядок интеграций с обоснованием + вердикт по гипотезе Z-Bericht (работает / работает частично / не работает — и почему).

## R2. Конкуренты и соседи GastroBeleg

**Зачем.** Питч и слайд дифференциации строятся на утверждении: «никто не работает на уровне позиции с автообновлением цен из накладных». Это надо доказать или скорректировать. Плюс полевому продажнику нужны ответы на «а чем вы лучше X».

**Наше позиционирование (проверяем против него):** попозиционный интеллект-слой между документами и DATEV, касса-агностик, для владельца (не для канцелярии). Ключевые фичи-дифференциаторы: детекция тихих повышений цен, сверка Lieferschein↔Rechnung, food cost / menu engineering на живых закупочных ценах, предконтировка SKR 70, Pfand-логика.

**Карта — четыре группы:**
1. **Generic Beleg-тулы**: GetMyInvoices, Candis, Finmatics, sevDesk, Lexware, BuchhaltungsButler. Вопросы: парсят ли ПОЗИЦИИ (не только сумму)? Есть ли гастро-фокус? Цены. Наша гипотеза: все работают на уровне документа.
2. **Гастро-закупки/food-cost**: Choco, REKKI, Apicbase, MarketMan, Supy, FoodNotify, Yurest, экосистема Delegate/gastromatic. Кто активен в Германии, что именно делают (заказы? инвойсы? рецептуры?), цены, целевой размер ресторана, автозахват цен из счетов есть?
3. **WaWi-модули POS** (Gastronovi, Lightspeed, Vectron): насколько глубока их Warenwirtschaft — рецептуры? импорт счетов? автообновление цен? Или всё руками (наша гипотеза)?
4. **restdata.app** (Молдова) — наш референс-вдохновитель: текущие фичи, цены, признаки экспансии в DACH.

**Формат отчёта:** таблица-ландшафт; по каждому: попозиционный парсинг да/нет, автообновление цен да/нет, DATEV-экспорт да/нет, гастро-специфика да/нет, цена. Вывод: кто реально ближе всех к нашей позиции и чего ему не хватает; топ-3 самых опасных и почему.

## R3. Экономика Steuerberater для гастро-клиентов

**Зачем.** Три решения висят на этих цифрах: (а) прайсинг €89–149 — адекватен ли на фоне общих расходов ресторатора на бухгалтерию; (б) питч-формула «мы сокращаем счёт от StB, потому что данные приходят чистыми»; (в) KanzleiBeleg-питч для самих StB. Текущая оценка €150–400+/мес — экспертная, нужна фактура.

**Вопросы:**
1. StBVV-механика: как считается Buchführung (Gegenstandswert, Zehntelsätze) — что платит ресторан с оборотом €300–600k и 200–400 документами/мес? Искать реальные точки: форумы (juraforum, steuerberaten.de), прайс-страницы канцелярий, опросы, статьи «was kostet Steuerberater Gastronomie».
2. Наценка канцелярий на DATEV Unternehmen online для мандантов — практика?
3. Доказательства боли: жалобы StB на гастро-мандантов (бумажный хаос, Pfand, 7%/19%, чаевые, кассовые отчёты) — DATEV Community, форумы, блоги канцелярий. Собрать цитаты (перевести).
4. Как канцелярии сейчас получают документы от гастро (доля Upload mobil/UO против коробки бумаг против email)? Любая статистика диджитализации малых мандатов.

**Формат отчёта:** вилки гонораров с источниками; цитаты болей; вердикт: «мы сокращаем ваш счёт от StB» — правдоподобный клейм или нет; аргументы для KanzleiBeleg-питча.

## R4. Статус E-Rechnung-мандата

**Зачем.** Весь маркетинг InvoiceGen и часть питча GastroBeleg стоят на датах 2027/2028. Печатать их в лендинги/видео можно только после сверки с первоисточниками. Плюс версии форматов зашиваются в ядро генерации.

**Вопросы:**
1. Актуальная законодательная линия обязанности ВЫСТАВЛЕНИЯ (2027 >€800k, 2028 все): изменения, законопроекты, политическая дискуссия? Первоисточники: письма BMF, gesetze-im-internet, разъяснения IHK.
2. Текущие версии: XRechnung (какая, с какой даты), ZUGFeRD (версия, профили), анонсы следующих версий. Где живут официальные спецификации (KoSIT, FeRD).
3. Kleinunternehmer после реформы 2025 (§19 UStG): обязанности приёма/выставления, пороги.
4. Бонус: статистика/оценки, сколько бизнесов ещё не готово к e-Rechnung (размер волны).

**Формат отчёта:** верифицированный таймлайн + матрица версий + список маркетинговых клеймов, которые можно делать безопасно (с формулировками).

# PRIORITY 1 — формирует решения следующей фазы

## R5. Конкуренты и SEO-ландшафт InvoiceGen

**Зачем.** Дизайн InvoiceGen стартует после этого ресёрча. Наши гипотезы дифференциации: (1) бесплатный E-Rechnung-VIEWER («получил XRechnung — не могу открыть» — боль миллионов с 2025) и VALIDATOR (KoSIT) как SEO-магниты — гипотеза, что ниша пуста; (2) настоящий DATEV-экспорт; (3) мост к StB. Паритетная база (что должно быть как у всех): анонимное создание счёта за 2 минуты, PDF+XRechnung+ZUGFeRD, §19-режим, Mahnung, статусы, мультиязычный UI.

**Что уже известно про easyerechnung.de** (бенчмарк): Free 3 счёта/мес без вотермарки, Pro €7,99, Business €19,99 (мультипрофили, доступ StB), XRechnung/ZUGFeRD, Mahnwesen, аналитика+налоговый прогноз, UI DE/EN/RU/TR, «серверы в Германии».

**Вопросы:**
1. Глубокий teardown easyerechnung.de: полный фичелист по тарифам, лимиты, онбординг-флоу, SEO-футпринт (какие страницы ранжируются; оценка трафика по бесплатным инструментам), слабости в отзывах.
2. Остальные бесплатные/дешёвые генераторы под DE: инструменты типа rechnung-schreiben.de, Zervant, Billomat, FastBill, бесплатные тиры sevDesk/Lexware, Kleinunternehmer-специфичные. Таблица: форматы (PDF/XRechnung/ZUGFeRD), валидация, цена, требуется ли аккаунт.
3. Карта запросов (бесплатные данные: автокомплит Google, вопросы People-also-ask, тайтлы конкурентов): кластеры вокруг Rechnung schreiben / XRechnung / ZUGFeRD / E-Rechnung Pflicht / Rechnungsvorlage — где tool-интент, где info-интент.
4. Кто ранжируется по «XRechnung öffnen/anzeigen/lesen» и «XRechnung validieren/prüfen» — правда ли ниша Viewer/Validator пуста?

**Формат отчёта:** таблица конкурентов + карта кластеров + вердикт по каждой гипотезе дифференциации (подтверждена/опровергнута/скорректирована).

## R6. Партнёрство и интерфейсы DATEV

**Зачем.** Экспорт в DATEV — интеграция №1 всей экосистемы и главный аргумент StB-канала. Статус партнёра DATEV-Marktplatz снимает последние сомнения канцелярий (там сидят Finmatics, Candis — наши соседи по нише). Нужно понять цену входа и техническую дорогу.

**Вопросы:**
1. DATEV-Marktplatz: требования к партнёру, стоимость, сроки, техническая сертификация — что нужно стартапу для листинга? Есть ли ступени (référencé vs. full partner)?
2. Технические интерфейсы для третьих сторон: DATEVconnect (online/offline), Belegbilderservice, Buchungsdatenservice, API Unternehmen online — что открыто ISV, доки, sandbox. Что реально нужно для сценария «передать предконтированные проводки + образы документов в канцелярию манданта».
3. Прецеденты: как технически интегрировались Finmatics / Candis / GetMyInvoices (какой интерфейс, какой статус)?
4. Минимальный жизнеспособный экспорт для MVP БЕЗ партнёрства: форматы DATEV-CSV/Buchungsstapel, которые канцелярия может импортировать руками — ограничения?

**Формат отчёта:** варианты интеграции, ранжированные по реализуемости для MVP vs. позже; чеклист партнёрской программы; рекомендация «что делаем в MVP, что в Phase 2».

## R7. Выписки платформ доставки (Lieferando / Wolt / Uber Eats)

**Зачем.** Идея «истинная маржа доставки по блюдам» (см. Приложение A, идея 18): ресторатор видит выручку платформы, но не видит, что после комиссии 13–30%, упаковки и food cost половина позиций в доставке убыточна. Выписки платформ — документы, потенциально заходят в наш обычный ingestion. Никто в Belegtools этого не делает.

**Вопросы:**
1. Что содержат выписки/абрехнунги каждой платформы (разбивка комиссий, данные по заказам, уровень продукта?) — help-центры, форумы селлеров, образцы структур.
2. API или экспорт данных для ресторанов есть?
3. Существуют ли в DACH инструменты аналитики прибыльности доставки?
4. Актуальные диапазоны комиссий по моделям (доставка платформой vs. своя).

**Формат отчёта:** матрица доступности данных по платформам + вердикт реализуемости фичи (полная по блюдам / только агрегатно / нереализуема) + есть ли конкурент.

## R8. Юридические границы (StBerG / RDG / GoBD)

**Зачем.** Три фичи ходят по краю: «отложите ~€X на Umsatzsteuer» (витрина собственных данных), «рекомендованная цена блюда для маржи» (бизнес-консалтинг, не налоговый — предположительно нерегулируем), «prüfungssicher архив» (GoBD-клейм). Нужен словарь безопасных формулировок до написания UI-текстов, и понимание, чем подкреплять GoBD-клеймы.

**Вопросы:**
1. Где граница для не-StB софта: какие формулировки безопасны («Information», «basierend auf Ihren Daten») vs. рискованны («Empfehlung», «Sie sollten»)? Найти кейсы Abmahnung против финтех/лигалтех (окружение Lexoffice, прецеденты smartlaw/wenigermiete по аналогии из RDG).
2. Безопасно ли показывать «USt-резерв из ваших данных»? Безопасна ли «рекомендованная цена блюда» (проверить: ценообразование = нерегулируемый бизнес-консалтинг)?
3. GoBD-чеклист для клейма «prüfungssicher»: варианты подтверждения (IDW PS 880-тестат? провайдеры GoBD-Testat, стоимость), на что ссылаются конкуренты в своих клеймах.
4. Хранение: актуальные сроки (§147 AO — было 10 лет, недавняя реформа сократила часть до 8 — проверить точно) и следствия для нашего архива.

**Формат отчёта:** гайд «можно/нельзя» по формулировкам (с примерами на немецком) + опции сертификации со стоимостью + правки в продуктовые тексты.

# PRIORITY 2 — стратегический горизонт (под питч партнёру/инвестору)

## R9. Размер рынка DACH

**Зачем.** TAM/SAM/SOM для партнёрского питча и санити-чек амбиций.

**Вопросы:** число гастро-бизнесов Германии по размеру (DEHOGA, Statistisches Bundesamt) — сколько независимых до ~50 мест vs. сети; число Kleinunternehmer/фрилансеров (рынок InvoiceGen); число StB-канцелярий, средние портфели мандатов, доля на DATEV; для «горизонта вертикалей» — число малых производств (пекарни, мясные, столярки до 20 сотрудников).

**Формат отчёта:** TAM/SAM/SOM-скетч с источниками, готовый к вставке в питч.

## R10. QR-меню и меню-тех + LMIV

**Зачем.** Цепочка «скан меню» (Приложение A, идеи 24–29): фото Speisekarte → каталог блюд → черновики рецептур → food cost → QR-меню, знающее свою себестоимость. Гипотеза: ни один QR-сервис не связан с закупочными данными.

**Вопросы:** кто предлагает QR/цифровые меню в DACH, цены, есть ли у кого связь с себестоимостью (гипотеза: нет); LMIV-обязанности по 14 аллергенам для ресторанов — точные требования, штрафы, практика контроля (Lebensmittelüberwachung); как рестораны ведут аллергенные карты сейчас.

**Формат отчёта:** короткий ландшафт + выжимка LMIV-требований + вердикт по гипотезе.

## R11. Канал грюндеров (Gründungszuschuss)

**Зачем.** Сегмент C нашей сегментации: «хочу открыть ресторан» — не клиент, а воронка (Gründer-Modus: бизнес-план с реальными региональными ценами закупок → открылся → стал клиентом с нулевым CAC). Известные факты о программе — в разделе «Что уже выяснено».

**Вопросы:** объём — сколько одобрений Gründungszuschuss в год (статистика BA), доля гастро среди грюндеров; кто консультирует гастро-основателей (IHK Gründungsberatung, рынок AVGS-коучей, Gründerzentren) — собрать топ-20 кандидатов в партнёры с контактными точками; какие инструменты бизнес-планирования они используют сейчас.

**Формат отчёта:** оценка размера канала + список партнёров + идея минимального Gründer-Modus MVP.

## R12. Прецеденты Einkaufsgemeinschaft

**Зачем.** Эндшпиль-идея (Приложение A, идея 23): при 30+ ресторанах в городе агрегированный спрос = переговорная сила перед поставщиками («12 ресторанов Дюссельдорфа берут 400 кг моцареллы в неделю — минус 7%»). Второй сетевой ров рядом с ценовым бенчмаркингом.

**Вопросы:** существующие закупочные кооперативы немецкого гастро (для сетей и независимых) — как устроены, комиссионные модели, почему независимые малые не покрыты; юридические формы для data-driven закупочной группы (eG? GbR? просто маклер-модель?); антимонопольные ограничения для такой агрегации есть?

**Формат отчёта:** саммари прецедентов + оценка жизнеспособности + юридическая форма-кандидат.

# ПРИЛОЖЕНИЕ A — Каталог продуктовых идей (карта всего, что обсуждалось)

> Это НЕ roadmap и НЕ скоуп MVP. Это полный бэклог идей для контекста:
> ресёрч-задания часто проверяют реализуемость или уникальность конкретных идей отсюда.
> Фазы предварительные, финальная приоритизация — отдельным документом.

## Группа 1. Ценовой интеллект (ядро дифференциации)
1. **Детекция тихих повышений цен** — алерт «Hollandia поднял 4 позиции за 60 дней, эффект ~€180/мес». Флагманская фича, фундамент бенчмаркинга. [ранняя Phase 2]
2. **Каскад в маржу блюд** — «масло подорожало → маржа шницеля упала 68%→63% → для сохранения цена 15,90». Требует рецептур. [Phase 2–3]
3. **Skonto-оптимизатор** — парсинг условий оплаты, «3 счёта выгодно оплатить до пятницы, упущено €47 скидок в этом месяце». [Phase 2]
4. **Сезонный планировщик** — из собственной истории цен: «через 3 недели сезон спаржи, в прошлом году −40%». Требует год данных. [Phase 3]
5. **Ценовой термометр рынка** — урезанный бенчмаркинг с первых 20–30 клиентов: индекс топ-20 стандартных позиций, opt-in «делюсь → вижу». Предшественник большого рва. [Phase 3]
6. **Региональный бенчмаркинг** — полный: «похожие итальянские рестораны региона: food cost 28–31%». Стратегический ров. [горизонт]

## Группа 2. Сверка и контроль (деньги, которые уже теряются)
7. **Сверка Lieferschein ↔ Rechnung** — «в накладной 10 кг, в счёте 12». Расхождения — 1–3% закупок. [ранняя Phase 2]
8. **Контроль Gutschrift** — рекламация отправлена, кредит-нота не пришла/не та сумма → напоминание. [Phase 2]
9. **Дубликаты счетов** — тот же счёт по email и бумагой, оплачен дважды. [Phase 2]
10. **Рейтинг надёжности поставщиков** — побочный продукт сверки: недовозы, ошибки, задержки Gutschrift по каждому поставщику. [Phase 2, почти бесплатно]
11. **Досье для переговоров с поставщиком** — годовой объём, история повышений, сравнение с ценами второго поставщика на пересекающиеся позиции. [Phase 2–3]

## Группа 3. Retention-механики (чтобы подписку не отменяли)
12. **Счётчик найденных денег** — каждый алерт конвертируется в €, копится: «нашли €1.840, подписка стоила €1.068». Главная анти-churn идея. [MVP-обвязка]
13. **Еженедельный WhatsApp-дайджест** — понедельник 8:00: закупки, повышения, недошедшие Gutschrift, Skonto-дедлайны. Петля привычки. [MVP-обвязка]
14. **Fälligkeiten-календарь** — платёжная неделя вперёд: «к оплате €4.300, из них 2 со Skonto». Микро-cashflow, ежедневное открывание. [ранняя Phase 2]
15. **«Спроси свой ресторан»** — чат по собственным данным: «сколько потратил на мясо в марте?». RAG поверх структурированных данных. [Phase 2]
16. **Betriebsprüfung-Modus** — GoBD-архив одним пакетом «под проверку»; продажа спокойствия. Легальный близнец Behördenpost без StBerG-риска. [Phase 2; клеймы зависят от R8]
17. **Onboarding «принесите коробку»** — оцифровка 3–6 мес бэклога при старте: история для алертов + психологическая инвестиция клиента. [процесс, с первых клиентов]

## Группа 4. POS-связка и меню (вторая половина уравнения)
18. **Аналитика платформ доставки** — истинная маржа Lieferando/Wolt по блюдам: «шницель в зале +€6,40, в доставке −€0,80». Зависит от R7. [Phase 2]
19. **Wareneinsatz-Quote еженедельно** — закупки÷выручка против нормы формата. Главный KPI гастро-консалтинга, строка №1 дайджеста. Требует POS/Z-Bericht. [ранняя Phase 2]
20. **Menu Engineering** — матрица маржа×популярность: звёзды/лошадки/загадки/собаки. Требует рецептур+POS. [Phase 3]
21. **Prime Cost** — WE-Quote + Personalkosten-Quote вместе (импорт суммы из Lohnabrechnung как документа): «67%, норма ≤65%». [Phase 3]
22. **Черновик заказа** — «пора заказывать: список, у кого какая позиция сейчас дешевле» → скопировать в WhatsApp торговому. Переход от аналитики к операциям. [Phase 3]
23. **Einkaufsgemeinschaft** — коллективные закупки на агрегированном спросе. Зависит от R12. [горизонт]

## Группа 5. Цепочка «скан меню» (холодный старт рецептур)
24. **Скан Speisekarte** — фото меню → каталог блюд с ценами продажи. Третий тип документа. [ранняя Phase 2]
25. **ИИ-черновики рецептур** — по названию+описанию блюда, матчинг ингредиентов с позициями из накладных клиента; старт с топ-10 блюд по выручке. [Phase 2–3]
26. **Демо «мини-аудит»** — на визите: фото накладной + фото меню → «ваш шницель за 14,90 — себестоимость ~4,60 по вашей же накладной». Убойное полевое демо. [версия для демо — раньше продукта]
27. **Меню-прайсинг против инфляции** — «с печати меню себестоимость +9%, вот 6 просевших блюд, рекомендованные цены с психологическими порогами». Зависит от R8 (формулировки). [Phase 3]
28. **Живое QR-меню** — хостим меню, цены меняются кликом, аллергены из рецептур (LMIV!) подставляются сами. Единственное QR-меню, знающее свою себестоимость. Зависит от R10. [Phase 3]
29. **Разведка по чужим меню** — фото/публичные меню соседей → ценовое позиционирование района. Работает с первого клиента. [Phase 3]

## Группа 6. Документы за пределами закупок
30. **Vertrags-Radar** — из повторяющихся счетов: реестр договоров (GEMA, вывоз мусора, кофемашина, Sky) со сроками Kündigungsfrist. [Phase 2]
31. **Абонементы кухни** — под-кейс: «ваши €740/мес фиксированных подписок». Момент прозрения на демо. [Phase 2]
32. **Versicherungs-Radar** — страховки из платежей + мягкий чек полноты («не видно Betriebsunterbrechung»); партнёрский лид брокеру. Осторожно с формулировками (R8). [Phase 3]
33. **Энерго-мониторинг** — счета Stadtwerke: тренд kWh/€, «электричество +18% к прошлому февралю — проверьте холодильники». [Phase 2, дёшево]
34. **Inventur-Assistent** — инвентаризация: владелец вводит только количества (или голосом), цены из последних накладных сами; точный WE за месяц; детектор Schwund («где 5 кг моцареллы?»). [Phase 3]
35. **Bankfähiger Report / Exit-паспорт** — годовой отчёт для банка/аренды/продажи бизнеса одной кнопкой. Редкий, но золотой момент. [Phase 3]

## Группа 7. Сегменты и каналы
36. **Три двери на сайте** — сегменты: A «действующий, хочет расти» (core, €89–149) / B «микро-гастро» (входной тариф €39–49: ingestion+DATEV+алерты) / C «хочу открыть». Продукт один, тарифы и онбординг разные.
37. **Gründer-Modus** — для сегмента C: план меню → food cost по реальным региональным ценам → каркас Finanzplan для банка/Gründungszuschuss. Бесплатно/символически = воронка+SEO+контент для агентства. Зависит от R11. [Phase 3]
38. **Onboarding-анкета** — 5 полей: посадочные места, формат, кухня, часы, (позже POS) → нормировка всех метрик (€/место, нормы WE по формату) и корректный бенчмаркинг. [MVP — просто поля, аналитика позже]
39. **Multi-Standort** — 2–4 точки: сравнение WE-Quote и закупочных цен между точками («точка A платит за молоко +6% у того же поставщика»), консолидация; тариф ×1,5–2. [Phase 3]
40. **Steuerberater-Marktplatz** — матчинг «ресторан ищет гастро-опытную канцелярию» внутри KanzleiBeleg; канал в обе стороны. [горизонт]
41. **Голосовой intake** — наговорил в WhatsApp: «ящик салата гнилой, сделай рекламацию» / «сколько должны Hollandia?». Кухня = среда без рук. Сквозная механика. [Phase 2–3]

## Отложено (не делать, не ресёрчить без отдельного решения)
- **Behördenpost** — расшифровка писем ведомств (Finanzamt и др.): StBerG/RDG-риск, отложено. Архитектура типов документов оставляет дверь открытой.
- **Вертикаль малого производства** (пекарни, столярки, Metzgerei) — структурно те же боли, но после PMF гастро. Ядро строится универсальным.
