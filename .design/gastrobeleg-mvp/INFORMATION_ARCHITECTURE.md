# Information Architecture: GastroBeleg — MVP

> Основано на `DESIGN_BRIEF.md`. Greenfield — роутинга/навигации ещё нет, эта IA задаёт их с нуля.
> Стек: Next.js App Router. Навигация: **bottom-tabs (телефон) → sidebar (desktop)**.
> Табы: **Скан · Документы · Аналитика · Ещё**. Роль Staff → отдельный упрощённый экран захвата.

## Navigation Model

- **Primary navigation (макс 4).** Нижние табы на телефоне, вертикальный sidebar на ≥ md:
  **Скан · Документы · Аналитика · Ещё**. «Скан» визуально выделен (центральная акцентная кнопка на
  мобиле). На desktop главный жест дублируется кнопкой «+ Документ» в шапке — sidebar-пункт «Скан»
  открывает тот же лист.
- **Secondary navigation.** Внутри разделов — контекстные табы/фильтры:
  - Документы: сегмент-контрол «На проверку / Все» + фильтры (поставщик, тип, период, статус).
  - Аналитика: переключатель периода + под-разделы (Обзор / Цены / Pfand).
  - Ещё: список-меню, ведёт в подстраницы (каталог, поставщики, экспорт, настройки).
  - Review-экран: адаптивный переключатель **«Фото / Позиции»** (телефон) ↔ split (desktop).
- **Utility navigation.** Аккаунт/локация-свитчер и уведомления — в шапке (аватар + название компании,
  переключение локации для мульти-локейшн тенантов). Помощь и правовое — в «Ещё».
- **Mobile navigation.** Нижние табы (fixed, safe-area aware). Глубокие страницы открываются стеком с
  кнопкой «Назад» в шапке. Никакого гамбургера в основном потоке — только для Staff-оболочки его тоже нет.

## Content Hierarchy

### Скан (`/scan`) — действие, не страница
1. **Крупная кнопка «Сфотографировать документ»** — единственная главная цель.
2. Вторичные пути: «Выбрать из галереи», «Загрузить PDF/файл».
3. Мелко: подсказка о мультизагрузке и email-адресе `docs-{tenant}@…` для пересылки.

### Документы (`/documents`)
1. **Очередь «На проверку»** — если есть документы, требующие внимания (низкая уверенность/валидация),
   они сверху с бейджем-счётчиком. Это то, ради чего пользователь заходит чаще всего.
2. Лента документов (карточки: поставщик · тип · дата · сумма · статус).
3. Фильтры/поиск — над лентой, сворачиваемые на мобиле.
4. Ниже: сумма за период / число документов (лёгкий контекст, без «дашборда»).

### Документ — review (`/documents/:docId`) — 80% ценного времени здесь
1. **Оригинал ↔ позиции** (split/табы) с подсветкой полей низкой уверенности — первично.
2. **Валидационный баннер** (расхождение суммы, дубликат, скачок цены) — сразу под шапкой, если есть.
3. Editable-строки позиций: qty · unit · цена · итог · НДС · **Pfand-флаг** · confidence.
4. Шапка документа: поставщик, тип, номер, дата, итог/НДС-своды.
5. **Кнопка «Подтвердить и провести»** — закреплена внизу, активна когда критические поля разрешены.
6. Вторично: ссылки на аудит-трейл и оригинал-файл.

### Аналитика / Обзор (`/insights`)
1. **KPI-плитки**: расходы за период, Δ цен (топ роста), число документов, остаток пакета.
2. **Топ подорожаний** — список товаров с ростом цены > порога (прямая ценность «где переплачиваю»).
3. Расходы по категории/поставщику/месяцу (график + разбивка).
4. **Pfand-баланс** по поставщикам (сводно, деталь — в под-разделе).

### Каталог (`/catalog`)
1. Таблица товаров (название · базовая единица · связей с поставщиками · последняя цена).
2. Незамапленные строки поставщиков — сверху как «требует сопоставления».
3. Деталь товара: конверсии единиц, связанные строки поставщиков, история цены.

### Экспорт / DATEV (`/export/datev`)
1. Выбор периода/документов.
2. **Предпросмотр стапеля**: раскладка по счетам, 7/19% split, Pfand-счёт отдельно.
3. **Обязательный тест-экспорт** перед первым реальным (CLAUDE.md §5.5) — заметный шаг.
4. Настройки маппинга счетов (SKR03 деф. / SKR04) — ссылка в `/settings/accounting`.

## User Flows

### Поток A — Захват документа (Owner/Manager)
1. Пользователь на любом экране → тап «Скан» (таб) или FAB.
2. Лист: Камера / Галерея / Файл.
3. Действие: снимает/выбирает.
   - Если это батч/мультистраничный PDF → система авто-разбивает на несколько документов.
   - Если дубликат (тот же поставщик+номер+сумма) → предупреждение на этапе проведения (не блокирует загрузку).
4. Карточка появляется в «Документы» со статусом **распознаётся** (не блокирующее ожидание).
5. По готовности — статус **на проверку**, бейдж на табе «Документы».

### Поток B — Захват (Staff)
1. Staff входит → сразу `/capture` (упрощённая оболочка, без табов).
2. Видит крупную кнопку «Сфотографировать» + ленту своих загрузок со статусами.
3. Снял → «Загружено ✓». Никакой проверки/аналитики — это делает Owner/Manager.

### Поток C — Проверка и проведение (сердце продукта)
1. `/documents` → тап по документу «на проверку».
2. Review-экран: оригинал + позиции, поля низкой уверенности подсвечены и первыми по вниманию.
3. Пользователь правит подсвеченные поля (тап по позиции → подсветка на фото).
   - Если незнакомая строка товара → popover маппинга (fuzzy-подсказки / создать новый) → **запомнить пару**.
   - Если валидация не сходится (qty×цена≠итог, сумма≠итог) → баннер с объяснением, правка на месте.
   - Если скачок цены > порога → мягкий флаг со старой/новой ценой.
4. Все критические поля разрешены → «Подтвердить и провести».
5. Документ становится **проведённым и неизменяемым** (дальше — только Storno). → возврат в очередь,
   счётчик «на проверку» уменьшается.

### Поток D — Первое сопоставление товара
1. В review встречается строка поставщика без маппинга.
2. Popover: fuzzy-подсказки по имени/EAN/артикулу + «создать товар в каталоге».
3. Выбор/создание → (опц.) задать конверсию единиц («1 Kiste = 24×0,33 л»).
4. Пара (поставщик, строка) сохранена → в следующий раз применяется автоматически, без вопроса.

### Поток E — Экспорт в DATEV
1. `/export/datev` → выбор периода/документов (только проведённые).
2. Предпросмотр стапеля: счета, 7/19%, Pfand отдельно.
   - Если маппинг счёта отсутствует → подсказка настроить в `/settings/accounting`.
3. **Тест-экспорт** (проверка формата) → затем реальный экспорт (скачивание/в DATEV Unternehmen Online).

### Поток F — Онбординг (минимальный)
1. `/signup` → создание тенанта (название, локация) — минимум полей.
2. Сразу `/scan` с подсказкой «Загрузи первый документ».
3. Обучение в контексте: первый review показывает подсказки; каталог/счета настраиваются по ходу
   первого документа, а не заранее (мастера нет).

## Content Growth Plan

- **Документы** — растут бесконечно. Дефолт-вид = «на проверку» (короткий). Архив «Все» —
  пагинация/бесконечный скролл + фильтры (поставщик, тип, период, статус) + поиск (номер, поставщик, сумма).
  GoBD: старое не удаляется (10 лет), поэтому нужен архивный паттерн и фильтр по годам.
- **Каталог / Поставщики** — растут медленно, стабилизируются. Таблица с поиском/сортировкой; «требует
  сопоставления» всегда всплывает наверх.
- **Аналитика** — не растёт «списком», а углубляется по времени: селектор периода, drill-down в товар/поставщика.
- **История цен / аудит-трейл** — append-only; показываем как хронологическую ленту с пагинацией.

## URL Strategy

- **Pattern:** `/<section>/<id>/<subview>` — плоско, читаемо, максимум 3 уровня.
  Разделы: `scan`, `documents`, `insights`, `catalog`, `suppliers`, `export`, `settings`, `more`, `capture`.
- **Dynamic segments:** `:docId`, `:itemId`, `:supplierId` — непубличные ULID/uuid (не последовательные,
  чтобы не угадывались; документы — чувствительные данные).
- **Query parameters:**
  - Фильтры/сортировка списков: `?filter=review|all&supplier=…&type=…&from=…&to=…&sort=…` (DD.MM.YYYY в UI,
    ISO в query).
  - Пагинация: `?page=` или курсор `?cursor=` (бесконечный скролл в архиве).
  - Период аналитики: `?period=month|quarter|year&month=YYYY-MM`.
- **Локация (мульти-локейшн тенант):** активная локация в состоянии/сессии, не в URL (чтобы ссылки не
  ломались при переключении); при необходимости — `?location=` как опциональный override.
- **Роли:** Staff редиректится на `/capture`; попытка зайти на закрытые URL → редирект туда же.
